# 本地部署控制台项目需求分析文档（SRD）

## 1. 文档信息

- 项目代号：UniNode Console
- 文档版本：v1.0
- 文档类型：需求分析（可直接进入研发）
- 适用范围：本地部署、单组织使用、网络运维与多节点协同管理
- 来源依据：本次完整协作过程中的用户诉求、反复确认内容、痛点与偏差复盘

## 2. 背景与问题定义

用户原始目标是构建“多设备统一网络管理体系”，覆盖：

- 办公网/LAN 内设备稳定访问全球网络；
- 外网/5G 场景通过 Clash 订阅或 Tailscale Exit Node 稳定访问；
- 树莓派与小主机同时承担旁路由、Tailnet 节点、NAS 服务；
- 基于统一虚拟局域网支持多 Agent 协同；
- 全过程可追踪、可回滚、可验证。

在历史项目中出现的问题并非“技术无法实现”，而是“目标与实现偏离、资产混杂、路径不收敛”：

- 文档、脚本、配置存在多入口，无法快速确认“当前真相”；
- 历史路径与现行路径混杂，自动化脚本默认指向错误位置；
- 变更流程缺乏强门禁，执行层面容易先改后证；
- 线上状态与仓库状态时有脱节，复盘成本高；
- 用户真实诉求是“纯净重启 + 可控交付”，而非继续在偏离基础上修补。

## 3. 核心用户与使用场景

### 3.1 核心用户

- 主用户：个人/小团队网络运维 owner（具备命令行基础，非专业 SRE）
- 次用户：协作者（需要按 runbook 执行标准步骤）

### 3.2 关键场景

- 场景 A：新建或重建项目，快速建立“唯一事实源”和执行骨架；
- 场景 B：执行分阶段网络变更（金丝雀->扩容->观察）；
- 场景 C：跨设备访问异常时快速定位并回滚；
- 场景 D：生成可审计的执行记录，用于后续复盘/交接；
- 场景 E：统一管理 NAS 同步与多 Agent 协同的前置网络条件。

## 4. 用户真实需求与痛点映射

| 用户真实诉求 | 当前痛点 | 产品必须解决 |
|---|---|---|
| 我只要“初衷目标”，不要历史偏差 | 旧资产污染、路径混杂 | 新项目强隔离，目标文档为唯一北极星 |
| 我需要可直接执行，不要概念化建议 | 缺少开发级规格与流程门禁 | 输出可开发文档+结构化执行流程 |
| 我需要安全推进，不希望误操作 | 线上改动风险高，回滚不统一 | 每一步强制验证标准与回滚步骤 |
| 我需要看见进度与状态 | 执行证据分散、不可追踪 | 控制台统一记录状态、门禁、证据 |
| 我需要跨设备一致体验 | 配置发布与消费链断裂 | 配置发布、命中验证、基线对比闭环 |

## 5. 产品目标（可衡量）

### 5.1 业务目标

- G1：将“网络治理项目”从文档驱动升级为“控制台流程驱动”。
- G2：把“步骤正确性”前置到执行前门禁，减少不可逆变更。
- G3：把“证据收集与回滚能力”产品化，降低人为遗漏。

### 5.2 成功指标（KPIs）

- KPI-1：首次初始化后 30 分钟内完成 Phase A/B（基线+联通）；
- KPI-2：关键变更流程 100% 具备验证命令与回滚命令；
- KPI-3：执行记录覆盖率 >= 95%（每个任务都有状态与证据引用）；
- KPI-4：异常恢复平均时长（MTTR）相比手工流程下降 40%；
- KPI-5：新增协作者 1 天内可独立执行标准批次。

## 6. 范围定义

### 6.1 In Scope（v1 必做）

1. 本地控制台（CLI）项目初始化与结构化工作区创建；
2. 目标文档绑定（北极星文档）与约束检查；
3. 分阶段执行编排（Phase A~G）；
4. 门禁机制（前置检查、执行检查、收口检查）；
5. 脚本执行代理（apply/rollback/bench/verify）；
6. 基线采集与结果归档；
7. 任务状态机（draft/running/blocked/passed/failed/rolledback）；
8. 一键导出执行报告（Markdown）。

### 6.2 Out of Scope（v1 不做）

- Web UI；
- 多租户/多团队权限系统；
- 云端托管与远程审计中心；
- 自动替用户做高风险线上操作（仅引导+门禁+执行代理）。

## 7. 功能需求（FR）

### FR-01 项目初始化

- 输入：项目根目录、目标文档路径
- 输出：标准目录结构、默认配置模板、执行计划骨架
- 验收：目录完整、路径引用一致、初始化日志生成

### FR-02 目标一致性校验

- 系统读取目标文档关键段（设备、拓扑、目标能力）
- 生成“需求清单快照”
- 后续所有任务必须绑定至少一个目标条目

### FR-03 阶段化执行引擎

- 支持 Phase A~G 定义、激活、暂停、回滚
- 每个阶段包含：前置条件、操作命令、验证命令、回滚命令、证据路径

### FR-04 门禁系统

- Pre-check：环境、依赖、脚本语法、配置完整性
- Runtime-check：命令执行返回码、关键字段非 NA、连通性阈值
- Post-check：证据归档、状态收口、变更摘要

### FR-05 证据与日志归档

- 自动创建 session 目录
- 保存命令执行摘要、关键输出、结果 JSON/CSV 路径
- 支持 “latest” 快速定位

### FR-06 配置发布与覆盖校验

- 支持配置模板校验（字段完整性、最小规则覆盖）
- 发布前自动校验，失败阻断

### FR-07 回滚编排

- 支持单步骤回滚与阶段级回滚
- 回滚动作必须记录结果并二次验证

### FR-08 报告生成

- 按阶段生成可读报告：执行内容、通过/失败、风险、后续建议
- 输出路径固定于 `reports/`

## 8. 非功能需求（NFR）

- NFR-1 可用性：CLI 在 macOS/Linux 上可运行（zsh/bash）；
- NFR-2 安全性：敏感值不落入版本库，支持 secrets 注入；
- NFR-3 稳定性：任何失败不应破坏已归档证据；
- NFR-4 可追踪性：所有阶段有唯一 session id；
- NFR-5 可维护性：新增阶段不需改核心引擎（配置驱动）；
- NFR-6 可观测性：失败必须给出可执行修复建议。

## 9. 约束与风险

### 9.1 技术约束

- 以本地脚本和 CLI 为中心，不依赖外部 SaaS；
- 需兼容已有脚本资产（shell + python）；
- 不假设所有节点都可被自动 SSH 管控。

### 9.2 主要风险

- R1：目标文档更新后未同步任务模板；
- R2：跨设备环境差异导致脚本行为不一致；
- R3：人为绕过门禁直接执行高风险命令；
- R4：历史配置中的敏感值泄露。

### 9.3 风险缓解

- 目标文档变更触发“重新映射”提醒；
- 脚本执行前进行平台识别与前置探测；
- 默认只允许运行白名单命令；
- secrets 扫描与提交前检查。

## 10. 里程碑建议

- M1（第 1 周）：初始化框架 + 目标映射 + Phase A/B
- M2（第 2 周）：门禁系统 + 证据归档 + 报告生成
- M3（第 3 周）：配置发布与回滚编排 + Phase C/D
- M4（第 4 周）：NAS/Agent 协同流程接入 + 稳定性加固

## 11. 验收标准（Definition of Done）

项目可验收的最低标准：

1. 可从空目录初始化完整项目；
2. 可执行至少 2 个阶段并完成门禁；
3. 失败后可触发回滚并验证；
4. 可生成完整报告（含证据链接）；
5. 全过程不需要手动拼接文档才能复盘。
