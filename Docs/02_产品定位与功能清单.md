# 02 产品定位与核心功能清单

## 1. 风险先行

当前最容易失控的点，是把“多设备统一网络管理”误解为一次性重做网络、NAS、订阅、Tailscale、Agent 调度、云发布的全套系统。实际证据表明，最紧急的问题不是缺少更多网络能力，而是缺少把已有脚本、配置、基线、回滚、报告串起来的控制台。

必须先解决：
- 证据不足却被文档写成 PASS。证据：`P0_COMPLETION_REPORT_2026-04-20.md`、`mobile-compare/manual_20260421_120408/compare_result.json`。
- 事实源入口存在，但字段与引用仍漂移。证据：`CURRENT_SOURCE_OF_TRUTH.md`、`network_facts.env`、`README.md`。
- Batch1 已完成局部金丝雀，但未证明全网扩围。证据：`BATCH1_MINIPC_CANARY_CHANGE_ORDER_2026-04-22.md`、`BATCH1_24H_OBSERVATION_CHECKLIST_2026-04-23.md`。
- 配置中存在敏感材料形态，不能直接作为多 Agent 上下文或公开同步产物。证据：`configs/sing-box-config.deploy.json`、`configs/clash-subscription.runtime-safe.yaml`、`sync_to_github.sh`。

## 2. 一句话产品定位

一个本地部署的多设备网络运营控制台，把家庭/办公网络、VPS、Tailscale、Clash、NAS 与 Agent 协同的变更过程变成可验证、可回滚、可审计的工程流程。

## 3. 目标用户画像

### Primary User：个人/小团队的技术负责人

- 同时维护办公网络、家庭网络、VPS、Tailscale、Clash、NAS 与多终端设备。
- 需要在 Mac、Windows、Linux、iPhone、iPad、Android 上稳定访问全球网络与私有服务。
- 能读懂命令和配置，但不希望每次故障都重新翻历史文档。
- 需要让 AI Agent 协作，但担心 Agent 引用旧路径、误判事实、泄漏凭据。

证据：`多设备统一网络管理项目配置情况及功能目标.md`、`CURRENT_SOURCE_OF_TRUTH.md`。

### Secondary User：被交接的运维执行者

- 可能零基础或只会按步骤操作 ASUS UI、终端命令、客户端刷新订阅。
- 需要清楚知道点击哪里、执行什么、成功长什么样、失败如何回滚。

证据：`BATCH1_MINIPC_CANARY_CHANGE_ORDER_2026-04-22.md` 中修订为 Path A/Path B，并补充 ASUS UI 精确步骤。

### Tertiary User：协作 Agent

- 需要读取事实源、阶段状态、证据索引、风险清单。
- 不应直接读取旧归档或明文 secret。

证据：`多设备统一网络管理项目配置情况及功能目标.md` 中的 OpenClaw/Hermes Agent 协同目标。

## 4. 核心价值主张

- 少折腾：先稳定可用，再做性能优化；所有动作都必须有 stop condition。
- 不误判：模板、空样本、NA 样本不能被当成真实成功证据。
- 可回滚：每个动作绑定回滚命令与回滚后复测。
- 可交接：把散落文档变成阶段化执行单与报告。
- 可审计：每个判断都能追溯到文件、命令输出或人工签收。
- 可协作：多 Agent 使用同一事实包，避免路径漂移和事实源分裂。

## 5. MVP 功能清单（必须做）

### MVP-01 本地项目初始化

能力：
- 创建 `app.yaml`、`assets.yaml`、`phases.yaml`、`secrets.policy.yaml`。
- 导入现有 `network-audit-2026Q2/`。
- 生成当前 evidence index。

验收：
- 能识别 `README.md`、`CURRENT_SOURCE_OF_TRUTH.md`、`network_facts.env`。
- 能提示 `README.md` 中 `NETWORK_TOPOLOGY.md` 引用当前缺失。

证据来源：
- `README.md`
- `CURRENT_SOURCE_OF_TRUTH.md`
- `network_facts.env`

### MVP-02 资产与事实源检查

能力：
- 管理终端、路由、边缘节点、VPS、腾讯云、服务、端口。
- 标记 required / optional / unknown。
- 检查空字段、重复 IP、悬空路径。

验收：
- `TAILSCALE_BACKUP_GW_IP` 与 `TAILSCALE_EPIXNAS_IP` 为空时必须列为阻塞项。

证据来源：
- `network_facts.env`

### MVP-03 证据索引与有效性判定

能力：
- 扫描 bench、results、mobile-compare、fingerprints、subscription-hits。
- 区分真实证据、模板、空快照、无效样本。

验收：
- 初始 NA bench 被判定为无效。
- 复测 HTTP 200 bench 被判定为有效但只覆盖当前 host/scenario。
- mobile compare `insufficient_data` 被判定为阻塞。
- subscription hits 只有 template 时被判定为阻塞。
- 空内容 SHA-256 指纹被判定为可疑。

证据来源：
- `bench/20260422T021827Z/pc_direct.json`
- `bench/20260422T022825Z/pc_direct.json`
- `mobile-compare/manual_20260421_120408/compare_result.json`
- `subscription-hits/hits.csv.template`
- `fingerprints/epix/20260421T215802Z_baseline-local/fingerprint.sha256`

### MVP-04 阶段执行与门禁

能力：
- 支持 P0/P1/P2、Batch1/Batch2、移动实测、订阅发布。
- 每个阶段有 precheck、action、gate、rollback、evidence_required。
- 支持 dry-run 与人工确认模式。

验收：
- Batch1 初始 NA 样本阻止切换。
- Batch1 复测样本通过后可进入 canary。
- 24h 观察未满足 6 个 checkpoint 时不能进入 Batch2。

证据来源：
- `BATCH1_MINIPC_CANARY_CHANGE_ORDER_2026-04-22.md`
- `BATCH1_24H_OBSERVATION_CHECKLIST_2026-04-23.md`

### MVP-05 回滚库与恢复报告

能力：
- 维护每类变更的回滚动作。
- 回滚后自动要求复测项。
- 生成 rollback report。

验收：
- Exit Node、ASUS Path A/B、订阅、VPS、移动证据至少各有一个回滚模板。

证据来源：
- `UNIFIED_OPS_RUNBOOK_2026-04-20.md`
- `RESTART_RECOVERY_GUIDE_2026-04-20.md`
- `SUBSCRIPTION_RELEASE_MANIFEST_2026-04-20.md`

### MVP-06 脱敏报告生成

能力：
- 生成阶段报告、审计报告、交接报告。
- 默认脱敏 UUID、password、private_key、token、证书私钥、订阅敏感 URL。

验收：
- 报告中不出现明文敏感值。
- 配置文件存在敏感字段时报告只输出字段名、文件路径、风险级别。

证据来源：
- `configs/sing-box-config.deploy.json`
- `configs/clash-subscription.runtime-safe.yaml`
- `sync_to_github.sh`

### MVP-07 Agent 上下文包

能力：
- 输出 `agent_context.json` 或 `agent_context.md`。
- 包含当前事实、阶段状态、阻塞项、证据索引、禁止引用路径、需用户拍板事项。

验收：
- Agent 上下文不能包含 secret 明文。
- Agent 上下文必须指出模板证据与真实证据差异。

证据来源：
- `CURRENT_SOURCE_OF_TRUTH.md`
- `P0_COMPLETION_REPORT_2026-04-20.md`

## 6. V1.1 功能清单（可选增强）

- Web UI：阶段看板、证据浏览、风险分级、报告预览。
- 设备探测：通过 SSH/Tailscale 读取服务状态，但默认只读。
- 计划任务：每日 facts audit、每 2-4 小时 observation checkpoint 提醒。
- Git 集成：提交前 secret scan、报告 diff、版本标签。
- ASUS 操作助手：生成更细的 UI 操作指引与截图绑定，不自动点击。
- 移动端采集助手：生成 CSV 填写表单、引导 Speedtest 固定 server。

## 7. V2 功能清单（长期增强）

- 安全执行器：受控 SSH 执行、最小权限、命令白名单、审批流。
- 真实可观测性：持续监控 Tailscale、sing-box、mihomo、Clash、NAS、Agent 端口。
- 自动回滚：门禁连续失败时按预案触发，但必须可配置为人工确认。
- NAS/Obsidian 同步运营：Syncthing/WebDAV/备份/冲突检测/恢复演练。
- OpenClaw/Hermes 协同面板：Agent 注册、网络可达性、任务队列健康、跨节点诊断。
- 多环境支持：家庭、办公室、腾讯云、Contabo、未来新增 VPS。

## 8. 暂不做

- 暂不自动修改 ASUS Web UI。
- 暂不自动发布生产订阅到客户端。
- 暂不默认执行高权限网络命令。
- 暂不重构 Clash/sing-box 配置语义。
- 暂不替代 Tailscale 管理后台。
- 暂不实现完整 NAS 产品。
- 暂不实现完整 Agent 编排平台。
- 暂不把历史归档全部迁移进新产品，只建立引用与禁止使用规则。

## 9. 产品边界

控制台是“运营编排与证据系统”，不是底层网络软件。它调用或包装现有脚本，例如 `bench_throughput.sh`、`run_mobile_compare.sh`、`apply_exitnode_rules_safe.sh`、`verify_rule_hit_coverage.sh`，但必须在门禁、证据、回滚、安全层面增加强约束。

首版产品的判断标准不是“网络速度提高多少”，而是：
- 能不能阻止错误扩围。
- 能不能证明某个结论是否有证据。
- 能不能让下一位执行者按报告安全完成维护。
- 能不能让 Agent 不再引用错路径或把模板当事实。
