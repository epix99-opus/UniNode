# 本地部署控制台项目产品设计文档（PR）

## 1. 文档目标

将需求文档中的目标转化为可直接开发的产品与技术设计，明确：

- 产品形态与交互；
- 模块边界与职责；
- 数据模型与目录规范；
- 核心流程与状态机；
- 开发拆解与测试策略。

## 2. 产品定义

### 2.1 产品形态

- 类型：本地部署 CLI 控制台（单机执行）
- 交互方式：命令行 + Markdown/JSON 报告
- 主要价值：把“网络治理流程”产品化，减少偏差与误操作

### 2.2 一句话描述

一个以“目标驱动 + 门禁执行 + 证据归档 + 可回滚”为核心的本地控制台系统。

## 3. 信息架构

### 3.1 标准目录

```text
UniNode/

    sessions/
    baselines/
    reports/
  templates/
  scripts/   # 可复用脚本资产
  tools/
```

### 3.2 核心实体

- Project：项目根与元数据
- TargetSpec：从目标文档抽取的目标结构
- Phase：阶段定义（A~G）
- TaskRun：一次执行实例（含状态与日志）
- GateResult：门禁检查结果
- Evidence：证据文件索引
- Report：阶段或全局报告

## 4. 核心流程设计

### 4.1 主流程（Happy Path）

1. `uninode init` 初始化项目
2. `uninode target bind` 绑定目标文档并抽取目标清单
3. `uninode phase list` 查看阶段
4. `uninode phase run <phase>` 执行阶段
5. `uninode report gen` 生成报告

### 4.2 状态机

任务状态：

- `draft` -> `running` -> (`passed` | `failed` | `blocked`) -> `rolledback`（可选）

阶段状态：

- `idle` / `in_progress` / `done` / `halted`

状态迁移规则：

- 未通过 Pre-check 不能进入 `running`
- `failed` 必须生成失败原因与建议
- 执行回滚后状态为 `rolledback`，并保留原失败记录

## 5. 模块设计

## 5.1 init 模块

职责：

- 创建目录结构；
- 写入默认配置模板；
- 初始化本地工作区元数据。

接口：

- `initProject(rootPath, options) -> InitResult`

## 5.2 target 模块

职责：

- 读取目标 Markdown；
- 提取设备、拓扑、核心目标；
- 生成目标索引 `target.snapshot.json`。

接口：

- `bindTarget(filePath) -> TargetSpec`
- `validateTarget(TargetSpec) -> ValidationResult`

## 5.3 phase 模块

职责：

- 加载阶段定义；
- 解析前置条件；
- 编排任务执行顺序。

接口：

- `listPhases()`
- `runPhase(phaseId, sessionId)`
- `rollbackPhase(phaseId, sessionId)`

## 5.4 guard 模块（门禁）

职责：

- 执行 pre/runtime/post checks；
- 输出结构化门禁结果；
- 阻断不满足条件的执行。

接口：

- `runPreChecks(context) -> GateResult[]`
- `runRuntimeChecks(context) -> GateResult[]`
- `runPostChecks(context) -> GateResult[]`

## 5.5 executor 模块

职责：

- 执行命令（白名单）；
- 捕获 stdout/stderr/exit code；
- 记录命令耗时与结果。

接口：

- `execStep(stepDef, context) -> StepResult`

## 5.6 evidence 模块

职责：

- 管理 session 目录；
- 归档证据索引；
- 支持 latest 查询。

接口：

- `saveEvidence(sessionId, artifact)`
- `indexEvidence(sessionId) -> EvidenceIndex`

## 5.7 report 模块

职责：

- 汇总阶段执行结果；
- 输出 Markdown/JSON 双格式报告。

接口：

- `generatePhaseReport(sessionId, phaseId)`
- `generateProjectReport(sessionId)`

## 6. 配置设计

### 6.1 app.yaml

- 项目级配置：工作区路径、日志级别、命令白名单、输出格式

### 6.2 phases.yaml

- 阶段定义（可配置化）
- 每阶段包含：
  - `id`
  - `name`
  - `preconditions`
  - `steps`
  - `verify`
  - `rollback`
  - `artifacts`

## 7. 命令设计（CLI）

### 7.1 一级命令

- `uninode init`
- `uninode target`
- `uninode phase`
- `uninode gate`
- `uninode evidence`
- `uninode report`

### 7.2 示例命令

- `uninode init --root /path/to/project`
- `uninode target bind --file ./目标.md`
- `uninode phase run C --session s20260501_001`
- `uninode phase rollback C --session s20260501_001`
- `uninode report gen --session s20260501_001 --format md,json`

## 8. 数据模型（简化）

### 8.1 TaskRun

```json
{
  "id": "task_001",
  "phaseId": "C",
  "sessionId": "s20260501_001",
  "status": "passed",
  "startedAt": "2026-05-01T10:00:00Z",
  "endedAt": "2026-05-01T10:02:10Z",
  "steps": [],
  "gates": [],
  "artifacts": []
}
```

### 8.2 GateResult

```json
{
  "gate": "precheck.syntax",
  "status": "pass",
  "message": "all scripts valid",
  "details": {}
}
```

## 9. 安全与权限设计

- 默认仅允许执行白名单命令；
- 高风险命令（路由、iptables、systemctl）要求二次确认；
- secrets 不进入仓库，运行时从本地受限文件读取；
- 报告输出对敏感字段做脱敏。

## 10. 可观测性设计

- 全局日志：`workspace/sessions/<id>/run.log`
- 步骤日志：`workspace/sessions/<id>/steps/<step>.log`
- 证据索引：`workspace/sessions/<id>/evidence.index.json`
- 阶段结果：`workspace/sessions/<id>/phase.<id>.result.json`

## 11. 开发建议与技术选型

## 11.1 推荐栈

- 语言：Python 3.11+（便于脚本整合与跨平台 CLI）
- CLI 框架：Typer 或 Click
- 配置与模型：Pydantic + YAML
- 日志：structlog 或标准 logging + JSON formatter
- 测试：pytest

## 11.2 代码分层

- `cli` 仅负责命令入参与输出；
- `core` 负责状态机与流程编排；
- `modules` 负责具体能力；
- `integrations` 封装 shell/tool 调用。

## 12. 测试策略

### 12.1 单元测试

- 配置加载与校验；
- 状态机迁移；
- 门禁规则判定；
- 报告生成器。

### 12.2 集成测试

- 从 init 到 phase run 的全链路；
- 模拟失败并验证 rollback 触发；
- 证据归档完整性检查。

### 12.3 验收测试

- 按 Phase A/B/C 最小闭环执行；
- 输出报告可被人工复盘并复现操作。

## 13. 迭代计划（建议）

- Sprint 1：初始化、目标绑定、基础 CLI
- Sprint 2：Phase 引擎、门禁、执行器
- Sprint 3：证据系统、报告系统、回滚编排
- Sprint 4：稳定性优化、模板完善、文档交付

## 14. 发布标准

- 命令集与文档一致；
- 关键路径覆盖测试通过；
- 失败场景可回滚并可追踪；
- 可在干净本地环境完成初始化与一次阶段执行。
