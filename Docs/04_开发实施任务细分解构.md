# 04 开发实施任务细分解构

目标：把 `03_PRD_本地部署控制台产品.md` 拆解为工程团队可直接排期、开发、测试、验收的实施任务。  
产品：UniNode Ops Console。  
推荐技术栈：React + TypeScript + Vite、Python FastAPI、SQLite、YAML 配置、SSE/WebSocket 事件流、本地文件证据库。

## 1. 总体实施策略

先做可视化只读控制台和 Cursor 自动化检查，再做审批式配置，最后做长期运营和多 Agent 协同。不要一开始就自动改生产网络。设备短时离线、断电、未接通是正常状态，MVP 必须能初始化、展示、提示人工动作，而不是失败退出。

工程优先级：

1. 导入与事实源。
2. 可视化拓扑与健康。
3. 证据索引与门禁。
4. Cursor 自动化任务包。
5. 报告与审计。
6. 审批式执行与回滚。
7. NAS/Obsidian 与 OpenClaw/Hermes 深度协作。

## 3. MVP 任务包

### Task 0：项目骨架

目标：建立前后端与配置目录，能启动空控制台。

交付：

- `apps/api` FastAPI 服务。
- `apps/web` React 控制台。
- `configs/app.yaml`。
- `data/` 运行目录。
- `README` 启动命令。

验收：

- `pnpm dev` 或等价命令能启动前端。
- `uvicorn uninode.main:app` 或等价命令能启动 API。
- `/healthz` 返回 OK。
- 首页能显示 UniNode Ops Console 标题和空状态。

### Task 1：配置加载与路径校验

目标：读取 app/source/workspace 配置，检查路径存在性，但不因设备离线失败。

交付：

- `config_loader`。
- 路径校验 API：`GET /api/config/status`。
- 错误模型：`CONFIG_ERROR`、`SOURCE_MISSING`、`DEVICE_OFFLINE_EXPECTED`。

验收：

- 源路径 `/Users/epix/Dev/TraeDev/contabo` 可配置。
- 审计目录 `network-audit-2026Q2` 可识别。
- 设备 IP 不可达不影响初始化。

### Task 2：设备事实源模型

目标：建立 Device 数据模型和导入器。

交付：

- `Device` schema。
- `devices.yaml`。
- 从 `network_facts.env` 导入 IP/端口。
- API：`GET /api/devices`、`GET /api/devices/{id}`。
- 前端设备列表。

验收：

- 能看到华为、ASUS、miniPC、EpixNAS、Contabo VPS、腾讯云、终端设备。
- miniPC/EpixNAS 支持 `expected_online=false` 与 `human_action=power_on_if_check_required`。
- Tailscale IP 为空时标记为 `missing_fact`，不标记为系统失败。

### Task 3：服务模型

目标：把网络和应用能力建模为 Service。

交付：

- `Service` schema。
- 服务类型：vpn_subscription、transparent_gateway、tailscale、nas、obsidian_sync、agent_node、router。
- API：`GET /api/services`。
- 前端服务列表。

验收：

- Contabo VPS 有 VLESS/HY2/订阅服务。
- miniPC 有 mihomo/旁路由/Tailscale Exit Node 服务。
- EpixNAS 有 NAS/备用 Exit Node/Obsidian sync placeholder。
- OpenClaw/Hermes 可作为 agent service placeholder。

### Task 4：Evidence 扫描器

目标：扫描现有 bench、results、mobile-compare、fingerprints、subscription-hits、configs、docs。

交付：

- `Evidence` schema。
- 文件扫描器。
- bench JSON parser。
- mobile compare parser。
- CSV template detector。
- fingerprint empty hash detector。
- invalid JSON detector。
- API：`GET /api/evidence`、`GET /api/evidence/summary`。

验收：

- 初始全 NA bench 标记为 invalid。
- 有效 HTTP 200 bench 标记为 valid。
- `mobile-compare` 的 `insufficient_data` 标记为 blocked evidence。
- `hits.csv.template` 标记为 template_only。
- 空 SHA-256 指纹标记为 suspicious。
- 损坏 JSON 被记录为 invalid_json。

### Task 5：安全扫描与脱敏

目标：识别配置和脚本中的敏感字段，报告时脱敏。

交付：

- `secrets.policy.yaml`。
- secret scanner。
- redaction utility。
- API：`GET /api/security/findings`。
- 前端安全风险卡片。

验收：

- 能识别 UUID、password、private_key、token、auth key、订阅敏感 URL。
- 报告和 Agent 任务包不输出明文。
- 发现高风险 secret 时阻止发布类任务进入执行状态。

### Task 6：拓扑构建器

目标：根据设备、服务、路径关系生成拓扑。

交付：

- Topology graph model：nodes、edges、layers。
- 层：physical、tailscale、global_access、nas_sync、agent_collaboration。
- API：`GET /api/topology?layer=physical`。
- 前端拓扑页。

验收：

- 能显示华为 → ASUS → miniPC/EpixNAS → VPS。
- 能显示 5G/外网 → Tailscale → Exit Node。
- 能显示 NAS/Obsidian 与 Agent 协作占位路径。
- 离线设备不移除，只改变状态颜色和提示。

### Task 7：Dashboard

目标：提供可视化首页。

交付：

- 健康总览。
- 设备状态卡。
- 全球访问状态卡。
- Tailscale 状态卡。
- NAS/Obsidian 状态卡。
- Agent 协作状态卡。
- 安全风险卡。
- 待人工动作卡。

验收：

- miniPC 下线时显示“需要人工接通后检查”，不显示“架构失败”。
- 证据缺口显示为 evidence gap。
- Secret 风险显示为 security blocked。

### Task 8：Gate Engine

目标：对 evidence 和 job 运行结果做门禁判断。

交付：

- gate schema。
- gates：no_invalid_json、no_na_fields、mobile_has_valid_samples、subscription_live_hits_present、fingerprint_non_empty、secret_scan_pass、device_offline_policy。
- API：`POST /api/gates/evaluate`。

验收：

- Batch 初始 NA bench 被阻断。
- 移动端 insufficient data 被阻断。
- subscription 只有 template 被阻断。
- expected offline 设备不会阻断只读扫描，但会阻断需要设备在线的执行类任务。

### Task 9：Automation Job 模型

目标：定义只读检查、诊断、配置、修复、回滚、报告任务。

交付：

- `AutomationJob` schema。
- Job 状态机。
- automations.yaml 初始任务：
  - `check_global_access`
  - `check_tailscale`
  - `check_obsidian_sync`
  - `check_nas`
  - `check_agents`
  - `scan_security`
- API：`GET /api/jobs`、`POST /api/jobs/{id}/run-dry`。
- 前端自动化页。

验收：

- dry-run 只生成步骤，不执行生产命令。
- 离线设备被加入 human action，而不是 job failed。
- 每个 job 有 precheck、steps、gates、evidence_required。

### Task 10：Cursor Automation Bridge

目标：把控制台中的诊断/修复任务转换为 Cursor Agent 可执行任务包。

交付：

- AgentTask schema。
- Cursor provider。
- 任务包生成器。
- 任务约束：allowed_paths、denied_actions、expected_output_schema、redaction。
- API：`POST /api/agents/cursor/tasks`。
- 前端“交给 Cursor 检查”按钮。

验收：

- 生成任务包时不包含明文 secret。
- 明确要求 Cursor 只读或 dry-run。
- 输出要求包含：发现、证据路径、建议动作、是否需要人工开机。
- Agent 输出能作为 evidence 归档。

### Task 11：报告生成

目标：生成当前状态报告、故障报告、任务报告、Agent 上下文。

交付：

- report generator。
- 模板：
  - current_ops_report
  - evidence_gap_report
  - security_report
  - agent_context
  - incident_report
- API：`POST /api/reports/{type}`。

验收：

- 报告有证据路径。
- 报告无明文 secret。
- 报告区分临时离线、证据不足、真实故障。
- 可写入 `Docs/`。

## 4. V1 任务包

### Task 12：受控本地执行器

目标：在审批后执行白名单命令。

交付：

- allowlist。
- timeout。
- stdout/stderr capture。
- exit code。
- cancel。
- run events。

验收：

- 默认禁用生产写操作。
- 执行前必须审批。
- `bench_throughput.sh` 可作为只读任务执行。
- 高风险命令被拒绝。

### Task 13：Tailscale 集成

目标：读取 Tailnet 设备、Exit Node、route、key 状态。

交付：

- Tailscale CLI adapter。
- 可选 Tailscale API adapter。
- 节点在线/离线。
- key 过期提醒。
- Exit Node 标记。

验收：

- API token 缺失时显示配置缺口。
- 离线节点进入 expected offline 或 unexpected offline。
- 不提供 VPN 连接本身，只监控和辅助配置。

### Task 14：Clash/mihomo 集成

目标：检查本地/旁路由 Clash/mihomo controller 状态和订阅命中。

交付：

- controller adapter。
- proxy group 状态。
- rule hit 采集入口。
- 订阅版本摘要。

验收：

- controller 不可达时提示可能设备未开机或服务未启动。
- hits.csv 缺失时生成采集任务。

### Task 15：NAS/Obsidian Sync 集成

目标：把 NAS/Obsidian 从目标口号变成可检查服务。

交付：

- sync service abstraction。
- WebDAV health check。
- Syncthing health check。
- CouchDB/LiveSync health check。
- backup marker check。

验收：

- 用户可选择同步方案。
- 未选择时显示 `sync_service_not_selected`。
- 已选择时检查服务可达、最近同步、备份点。

### Task 16：Incident Center

目标：故障分类、处理建议、自动化执行、回滚。

交付：

- Incident schema。
- severity。
- classification rules。
- recommended automations。
- rollback readiness。

验收：

- 全球访问慢能归类为 Freesky、VPS、Exit Node、订阅、证据不足。
- 设备离线能归类为人工开机。
- Agent 越权请求被阻断。

## 5. V2 任务包

### Task 17：OpenClaw/Hermes Agent Registry

目标：登记多 Agent 节点和能力。

交付：

- Agent registry。
- endpoint health。
- capability tags。
- task handoff。
- agent context sync。

验收：

- Agent 节点能显示在线状态。
- Agent 拿到统一 facts/evidence。
- Agent 输出能归档。

### Task 18：持续调度

目标：把检查变成周期任务。

交付：

- scheduler。
- 每日检查。
- 每周报告。
- 24h observation checkpoint。
- notification hook。

验收：

- 设备离线不造成告警风暴。
- 连续失败才升级 severity。

### Task 19：策略与权限系统

目标：支持不同角色和操作权限。

交付：

- roles。
- approvals。
- key store abstraction。
- audit log viewer。

验收：

- 只读用户不能执行配置。
- Agent 不能绕过审批。

### Task 20：配置生成与发布流水线

目标：将订阅、sing-box、mihomo、Tailscale 相关配置纳入版本化发布。

交付：

- config version。
- diff viewer。
- preflight。
- publish dry-run。
- rollback target。

验收：

- 发布前 secret scan。
- 发布前 rule coverage。
- 发布后 live hit evidence。

## 6. 测试与验收矩阵

MVP 必须通过：

- 导入现有审计目录。
- 正确识别设备临时离线。
- 正确识别 evidence gap。
- 正确识别 secret risk。
- 可视化拓扑可打开。
- Cursor 任务包可生成。
- 报告可生成且脱敏。
- dry-run 不执行生产命令。

V1 必须通过：

- 白名单执行器可运行只读命令。
- Tailscale 状态可读取。
- Clash/mihomo 状态可读取。
- NAS/Obsidian 有至少一种同步方案检查。
- Incident Center 可创建、分类、关闭。

V2 必须通过：

- OpenClaw/Hermes 节点注册。
- 周期检查与报告。
- 权限与审批。
- 配置发布流水线。

## 8. 工程验收门槛

每个任务完成时必须提供：

- 代码变更清单。
- 测试结果。
- UI 截图或 API 响应样例。
- 对应 PRD 条款。
- 风险与未完成项。

任何任务不得：

- 默认执行生产网络变更。
- 将 secret 输出到日志、报告或 Agent 上下文。
- 把设备离线直接当作架构失败。
- 把模板证据当作真实证据。
